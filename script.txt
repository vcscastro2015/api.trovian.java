ESTRUTURA DOS DTOs (MODELOS DE DADOS)
================================================================================

OrdemServicoDTO:
- id: Long
- numeroOs: String (obrigatório, max 50 chars)
- veiculoId: Long (obrigatório)
- veiculoPlaca: String
- motoristaId: Long (opcional)
- motoristaNome: String
- tipoManutencao: TipoManutencao (obrigatório)
- kmVeiculo: Integer
- dataAbertura: LocalDate (obrigatório)
- dataPrevista: LocalDate
- dataConclusao: LocalDate
- status: StatusOrdemServico (obrigatório)
- descricaoProblema: String (max 5000 chars)
- diagnostico: String (max 5000 chars)
- valorTotal: BigDecimal
- observacoes: String (max 5000 chars)
- itens: List<ItemManutencaoDTO>

ItemManutencaoDTO:
- id: Long
- ordemServicoId: Long
- tipo: TipoItemManutencao (obrigatório - SERVICO ou PECA)
- descricao: String (obrigatório, max 500 chars)
- quantidade: Integer (obrigatório, min 1)
- valorUnitario: BigDecimal (obrigatório, min 0.01)
- valorTotal: BigDecimal (calculado automaticamente)
- fornecedorId: Long
- fornecedorNome: String

PecaDTO:
- id: Long
- codigo: String (obrigatório, max 50 chars)
- descricao: String (obrigatório, max 500 chars)
- categoria: String (obrigatório, max 100 chars)
- estoqueMinimo: Integer (obrigatório, min 0)
- estoqueAtual: Integer
- valorMedio: BigDecimal (min 0.00)
- aplicacaoVeiculos: String (max 5000 chars)
- status: Boolean
- observacoes: String (max 5000 chars)
- estoqueBaixo: Boolean (calculado)

MovimentacaoEstoqueDTO:
- id: Long
- pecaId: Long (obrigatório)
- pecaCodigo: String
- pecaDescricao: String
- ordemServicoId: Long (opcional)
- ordemServicoNumero: String
- tipoMovimentacao: TipoMovimentacaoEstoque (obrigatório)
- quantidade: Integer (obrigatório, min 1)
- dataMovimentacao: LocalDateTime (obrigatório)
- valorUnitario: BigDecimal (min 0.00)
- observacao: String (max 5000 chars)
- usuario: String (max 100 chars)

AlertaManutencaoDTO:
- id: Long
- tipoAlerta: TipoAlerta (obrigatório)
- prioridade: PrioridadeAlerta (obrigatório)
- veiculoId: Long (obrigatório)
- veiculoPlaca: String
- ordemServicoId: Long
- ordemServicoNumero: String
- pecaId: Long
- pecaCodigo: String

ENDPOINTS DA API

BASE URL: /api (ajuste conforme sua configuração)

----- ORDENS DE SERVIÇO (/ordem-servico) -----

POST /ordem-servico
- Criar nova ordem de serviço
- Body: OrdemServicoDTO
- Response: OrdemServicoDTO (201 Created)

GET /ordem-servico?page=0&size=20&sortBy=id&direction=DESC
- Listar todas as ordens de serviço (paginado)
- Response: Page<OrdemServicoDTO>

GET /ordem-servico/{id}
- Buscar ordem de serviço por ID
- Response: OrdemServicoDTO

GET /ordem-servico/numero/{numeroOs}
- Buscar ordem de serviço por número
- Response: OrdemServicoDTO

GET /ordem-servico/status/{status}?page=0&size=20
- Buscar ordens por status (ABERTA, EM_ANDAMENTO, etc.)
- Response: Page<OrdemServicoDTO>

GET /ordem-servico/veiculo/{veiculoId}?page=0&size=20
- Buscar ordens de um veículo específico
- Response: Page<OrdemServicoDTO>

GET /ordem-servico/atrasadas
- Listar ordens de serviço atrasadas
- Response: List<OrdemServicoDTO>

PUT /ordem-servico/{id}
- Atualizar ordem de serviço
- Body: OrdemServicoDTO
- Response: OrdemServicoDTO

PATCH /ordem-servico/{id}/concluir?diagnostico=texto
- Concluir ordem de serviço
- Response: OrdemServicoDTO

DELETE /ordem-servico/{id}
- Deletar ordem de serviço
- Response: 204 No Content

================================================================================
FLUXOS DE INTEGRAÇÃO
================================================================================

1. INTEGRAÇÃO COM ABASTECIMENTO
   - Ao registrar abastecimento:
     * Chamar: POST /alerta-manutencao/verificar-abastecimento
     * Parâmetros: veiculoId, kmAtual
     * Verificar se retornou alertas novos
     * Exibir badge de notificação se houver alertas

2. INTEGRAÇÃO COM VIAGEM
   - Ao criar viagem:
     * Chamar: GET /alerta-manutencao/validar-veiculo-viagem/{veiculoId}
     * Se retornar false:
       - Bloquear criação da viagem
       - Exibir mensagem: "Veículo com manutenção crítica pendente"
       - Listar alertas críticos do veículo

3. INTEGRAÇÃO COM CONTAS A PAGAR
   - Ao concluir OS:
     * Gerar automaticamente conta a pagar
     * Vincular à categoria "Manutenção"
     * Vincular ao veículo
     * Valor = valorTotal da OS
     * Fornecedores dos itens como opções de pagamento

4. ALERTAS AUTOMÁTICOS
   - Verificação periódica (job/cron no backend):
     * Revisão preventiva (a cada 10.000 km)
     * Troca de pneus (80.000 km)
     * Estoque baixo de peças
     * OS atrasadas
   - Front-end deve:
     * Consultar alertas não lidos ao iniciar sessão
     * Atualizar contador de alertas periodicamente (polling ou WebSocket)

5. MOVIMENTAÇÃO AUTOMÁTICA DE ESTOQUE
   - Ao adicionar item tipo PECA em OS:
     * Verificar estoque disponível
     * Ao concluir OS:
       - Criar automaticamente MovimentacaoEstoque tipo SAIDA
       - Atualizar estoque da peça
       - Vincular à OS

================================================================================
FUNCIONALIDADES ESPECIAIS
================================================================================

1. GERAÇÃO AUTOMÁTICA DE NÚMERO DE OS
   - Formato sugerido: OS-YYYY-NNNN
   - Exemplo: OS-2024-0001
   - Sequencial por ano

2. VALIDAÇÕES NO FRONT-END
   - Não permitir concluir OS sem itens
   - Não permitir adicionar peça sem estoque suficiente
   - Validar datas (data conclusão >= data abertura)
   - Validar valores (não negativos)

3. CÁLCULOS AUTOMÁTICOS
   - Valor total do item = quantidade × valorUnitario
   - Valor total da OS = soma dos valores totais dos itens
   - Estoque baixo = estoqueAtual < estoqueMinimo

4. INDICADORES VISUAIS
   - Cores por status de OS:
     * ABERTA: azul
     * EM_ANDAMENTO: amarelo
     * AGUARDANDO_PECAS: laranja
     * CONCLUIDA: verde
     * CANCELADA: cinza
   - Badge de "ATRASADA" em OS com dataPrevista < hoje e status != CONCLUIDA
   - Badge de "ESTOQUE BAIXO" em peças

5. BUSCA E FILTROS
   - Autocomplete para seleção de:
     * Veículos (por placa)
     * Peças (por código ou descrição)
     * Motoristas (por nome)
     * Fornecedores (por nome)
   - Filtros combinados (múltiplos filtros simultaneamente)
   - Paginação em todas as listagens

6. EXPORTAÇÃO
   - Exportar listagens para CSV/Excel
   - Exportar relatórios para PDF
   - Imprimir OS (formato de ordem de serviço oficial)

OBSERVAÇÕES IMPORTANTES
================================================================================

1. Todas as respostas da API seguem o padrão REST
2. Erros retornam status HTTP apropriados (400, 404, 500, etc.)
3. Validações são feitas no backend (Bean Validation)
4. Paginação usa o padrão Spring Data (Page<T>)
5. Datas no formato ISO-8601 (yyyy-MM-dd ou yyyy-MM-dd'T'HH:mm:ss)
6. Valores monetários em BigDecimal (precisão de 2 casas decimais)
7. A API possui documentação Swagger/OpenAPI acessível em /swagger-ui.html
